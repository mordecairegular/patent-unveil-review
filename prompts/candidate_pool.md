# 候选池生成（T0：主题建模，双入口逻辑汇合点）

本文件用于**从业务领域或已有工作基础挖掘发明方向**，产物是 3–5 张候选主题卡和 1 个经用户终审的主推方向。它发生在"选定主题"之前，是 Step 3–8 主流程的**可选前置模块**。

**编号说明**：T0 是**逻辑汇合点**，不一定是时间上的第一步——材料入口下，Step 2 项目扫描先发生，其产出再喂给 T0。

## 何时执行 / 何时跳过

- **执行**：用户提出专利方向挖掘、候选池、GAP 发现、主题筛选类需求，且尚无选定主题时。
- **跳过**：用户已有明确主题和支撑材料 → 直接走 Step 1–8 主流程；用户在已有候选池上继续深挖某一主题 → 读该主题卡后进入 Step 5 案件级查新。

## 总原则（反定语膨胀）

本模块的目标**不是**通过堆叠限定条件制造形式上的新颖性，而是优先挖掘**具有自然技术边界的工程改进点**。默认优先从技术问题重定义、处理机制、控制闭环、数据到决策的转换、系统协同关系、异常处理方式中寻找区别；只有这些路径都走不通时，才允许用场景/对象/数据源限定形成窄化方案，且必须如实标注。

---

## 双入口

| 入口 | 适用 | 流程 |
|---|---|---|
| **材料入口（有工作基础，默认优先）** | 用户有代码、方案文档、系统说明、论文等 | Step 1 intake → Step 2 项目扫描 → 扫描产出（技术对象、数据流、控制动作、真实痛点）作为 T0.2 的输入 |
| **冷启动入口** | 只有业务方向和经验性痛点 | Step 1 intake（边界问题）→ 直接 T0.2；痛点标注"假设痛点，待用户确认" |

两个入口在 T0.2 汇合，产物相同。材料入口的痛点来自真实材料，质量优先级高于冷启动入口的假设痛点。（入口不用 A/B 编号，避免与查新 A/B/C/D 等级混淆。）

---

## 门 1：主题边界卡确认（用户确认后才继续）

生成**主题边界卡（Project Brief）**并请用户确认。至少包含：

| 字段 | 说明 |
|---|---|
| 业务方向 | 一句话 + 系统组成/技术对象 |
| 已有材料清单 | 可提供什么（代码/文档/数据/工程记录），无则写无 |
| 排除方向 | 明确不做的（如与业务无关的细分赛道、纯商业模型） |
| 优先方向 | 用户直觉上最想做/最贴业务的 |
| **申请目的** | 防御布局 / 成果发表 / 项目申报 / 产品保护 / 授权稳定性——直接影响可接受的保护范围与撰写策略 |
| **可接受创新幅度** | 只要机制性创新 / 接受小幅改进 |
| **是否允许窄化可发方向** | 允许则窄化备选进入推荐池；不允许则仅列出不推荐 |

用户确认（或修改后确认）门 1，方可进入 T0.2。

---

## T0.2 业务边界与场景拆解

按"设备/系统 → 运行环节 → 异常/痛点 → 现有处理方式 → 不足"拆解出 5–10 个技术场景。入口 A 须引用扫描产出的具体位置；入口 B 的每个场景标注"假设/用户确认"。

## T0.3 技术问题池（10–20 条）

- 每条痛点转译为**技术问题**：明确技术对象、场景、约束和缺陷；
- **禁止**保留"提高收益""降低成本""智能化"等商业/空泛表述——必须转译为可用技术手段解决的问题，转译不了的移入排除清单；
- 标注来源（扫描材料 / 用户陈述 / 假设）。

## T0.4 检索式设计

每个拟探针的候选方向 2–3 组检索词块（中文为主，必要时补英文），构造规则同 `prior_art_search.md` §A 第 3 点（语义块，不拆碎、不硬凑）。词块落档，供探针与后续案件级复用。

## T0.5 探针级查新（证据锚定，必做）

**目的**：给候选方向探针级初判，防止"模型自评 GAP"。**任何 A/B/C/D 等级只能在探针之后给出。**

- 范围与纪律见 `prior_art_search.md` §「查新分级」：每方向 2–3 组词块，`cnipa_epub_search.py` + `gp_xhr_search.py` 首页级，WebSearch（patents.google.com 域限定）补充；影响初判的高相关条目至少 1 条经稳定页复核；
- 结果写入**查新探针记录**（案件/项目目录，非 skill 目录），来源状态按 Step 5 证据模型标注（探针命中多为发现级）；
- **检索溯源纪律**：每个方向记录使用渠道、检索式、命中情况；未跑的渠道记"**未覆盖**"，**禁止**把"未检索"写成"未检出"；探针 0 命中只能写"探针范围内未检出"；
- 探针发现某方向已被占据时，按下方「探针冲突后的处理顺序」调整，**不得**第一反应加限定。

### 探针冲突后的处理顺序（换主轴优先）

1. 重新识别核心技术问题；
2. 切换发明主轴（异常工况处理 / 约束冲突仲裁 / 控制闭环 / 设备协同关系 / 数据到决策的转换机制 / 工程部署约束下的执行方式）；
3. 提炼新的处理机制；
4. 拆分为更具体但仍自然的工程问题；
5. **最后**才通过增加场景、数据源、设备对象或参数限定形成窄化方案。

### 限定依赖度（可测定义）

**限定依赖度 = 将候选方向与全部已知高相关文献区分开所需的 AND 特征数**（探针的副产品，不是模型自评）：

| 等级 | 判定 | 处理 |
|---|---|---|
| 低 | 1 个机制性特征即可区分 | 可主推 |
| 中 | 2 个特征组合区分（机制+少量限定） | 可主推/可发表 |
| 高 | ≥3 个限定叠加才与现有技术区分（如组合式检索需 3+ AND 词才 0 命中） | 窄化备选；须说明保护范围偏窄，并同时尝试挖掘更自然的主推方向 |

## T0.6 候选主题卡（3–5 张）

按 **`templates/candidate_topic_card.md`** 逐张填写。硬规则：

- **等级证据锚定**：探针级 A/B 的**最低证据要求**是至少一条真实检索命中或 0 命中组合，主题卡等级标注为 `A-探针` / `B-探针`；**案件级** A/B 另须满足 `prior_art_search.md` 的检索范围、阳性对照 ≥3 与来源状态门禁，案件级回写后方可去掉 `-探针` 后缀。未经探针的方向最高标"**未评级（低置信）**"，任何撰写动作前必须先补探针；
- **三层输出**：主推 / 可发表 / 窄化备选（对应限定依赖度低/中/高与创新幅度）；门 1 不允许窄化时，窄化备选仅列出不推荐；
- **双题名制**：简洁题名（≤25 字，"技术对象+核心处理动作+客体类型"；《专利审查指南》要求发明名称一般不超过 25 个字）+ 完整技术路线名；名称中原则上只保留一个最关键限定，其余移入权利要求/发明内容；简洁题名超 25 字标 WARN；
- **独权禁区**必须来自探针/查新确认的已占据框架（写公开号），不得凭想象填写；
- **暂停条件**写成可判定语句："若发现单篇覆盖【特征组合】，则【收缩至X / 与Y融合 / 放弃】"。

## 门 2：主题终审（用户确认后才进案件级查新）

输出推荐结论后，向用户提出 **3–5 个终审问题**（按本案裁剪）：

1. 推荐方向是否真实存在于你的业务/项目中？
2. 能否提供实施材料或工程依据？（列出具体清单：架构说明、数据样例、事件记录……）
3. 是否接受该方向的保护范围与创新幅度？（引用限定依赖度与分层结论）
4. 方案中的关键动作（控制、调节、引导类）在你的系统中是否真实存在或可实施？
5. 涉及商业规则的动作（价格、订单、排队）能否改写为技术化控制指令？（商业规则本身不得作为独权核心特征）

终审结论（谁确认、日期、每问答复）落档主题卡。**未过门 2 的方向不得进入案件级查新和交底书。**
门 2 确认的是**业务与材料边界**，不改判证据等级——A/B/C/D 始终由检索证据决定。

## 案后回填（领域包沉淀）

**节点**：探针轮结束、案件级查新结束、交底书交付、案件关闭——各回填一次，不等案件全部完成。

**回填对象**（保存在**用户项目目录**的领域包，如 `01_domain_pack/`；**内容属商业敏感信息，不得写入本 skill 公开仓库**）：

| 文件 | 回填内容 |
|---|---|
| 检索词库 | 本轮证明有效/遗漏的词块，中英对照 |
| 反例库 | 被打穿的方向类型（如"预测+优化调度裸组合"），附证据公开号 |
| 竞品与申请人 | 探针/查新证实活跃的申请人（未证实的不得标"活跃"） |
| 领域边界 | 排除方向的新增确认 |
| **独权禁区库（跨案）** | 各案确认的禁区条目集中登记（公开号+被占据框架），后续同领域案件直接复用 |

---

## 与主流程的衔接

- 门 2 通过的主题 → 建立案件目录 → **Step 3–4 轻量整合**（以主题卡为输入做融合检查与初筛表登记，**不重复挖掘**——主题卡即该主题的候选点档案，Step 5 回写同时更新初筛表与主题卡）→ Step 5 案件级正式查新（读 `prior_art_search.md` 全文执行）→ **门 3 查新证据复核签核**（最小签核字段见 `prior_art_search.md`「门 3」节；PSS 官方源核验为条件子项）→ Step 6 预览（门 4）→ Step 7–8；
- T0 的探针记录与主题卡随案件归档，案件级查新结论**必须回写**主题卡（等级、禁区扩充、暂停条件核销）；
- 本模块产物均落在**用户项目/案件目录**，不写入 skill 仓库目录。

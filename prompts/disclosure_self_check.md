# 交底书生成后自检（Step 8，内部执行）

## 局部执行契约

- **Purpose**：在交付前发现并修正技术、证据、权利要求、公式、图示和版式缺陷，给出受控交付状态。
- **Inputs**：定稿候选 `.md/.docx`、案件证据包、公式/数值清单、方案骨架和迭代产物（如有）。
- **Outputs**：修正后的交付文件、内部 PASS/WARN/FAIL、用户可见状态、交付检查记录和待补项。
- **Must**：机器门禁与语义自检都执行；查新二维评价与正文一致；关键数值独立核对；FAIL 先修正。
- **Must not**：把自检写进交底书正文；把内部 PASS 表述成专利性/可授权通过；用机器门禁替代语义审查；带关键缺陷定稿交付。
- **Completion criteria**：全部适用检查项已逐项处理，机器门禁非 FAIL，内部状态与用户可见映射正确，记录与实际交付一致。

自检结果用于**修订正文**，默认**不单独输出自检报告**；用户索要时可单独提供。**不得**将自检清单作为交底书一章写入正文。

## 8.1 逻辑与闭环

- [ ] 技术方案是否形成完整闭环（发现→处理→扩展/输出）？
- [ ] 模块之间关联关系是否清晰？上下游是否衔接？
- [ ] 分支样本（如边界样本、低置信度样本等）是否有明确处理路径？
- [ ] 依赖项（如类别中心、动态阈值等）是否有来源说明？
- [ ] 第五章「技术关键点」与第三章「系统流程」是否呼应？第五章以论点概述为主，技术细节在第三章。

### 权利要求一致性与联动闭环（A 路线必核）

> B 路线的对应检查见 §8.4「权利要求结构检查」；本小节适用于主流程（工程方法/软件/数据处理/控制测算）。发现问题直接改稿，并联动修订第三/四/五章。

- [ ] **必要特征零冲突**：独权主线（第五章欲保护点）中的每个步骤/特征，与正文及从属保护点中的「可选」「优选」「非必要」「可附加」表述是否**零冲突**？（反例：独权步骤写「经物理边界校验后确定输出值」，从属点却声明「该校验不是独立方法的必要特征」——同稿自相矛盾；二选一：从独权移除，或删除"非必要"声明）
- [ ] **逐特征规避测试**：对独权每个限定特征自问——删除它，方案是否仍完整成立？若成立，该特征为何在独权（通常应下移从属）；若竞争对手弃用该特征即可绕开（如某辅助信息层级被写成必选），是否已改为「至少一种」或「基础层级＋扩展层级」的弹性写法？
- [ ] **过窄参数不入独权**：具体数值（如半径 2.0 mm）、阈值常数（如 1.15）、迭代次数、收敛精度等实施细节只出现在实施例/从属保护点；独权只写「预设阈值」「预设收敛条件」？
- [ ] **联动闭环而非指标并列**：独权各步骤之间是否有**显式参数耦合/因果依赖**（步骤 N 的输出约束步骤 N+1 的行为）？若主线可拆成互不约束的并列计算（「计算指标 A、计算指标 B、按规则选择」），按 `patent_points_analyzer.md`「独权联动闭环检查」改写为联动表述或触发保护点重构。

### 跨视图一致性与保护支撑核对（两案代理复盘，主流程必核）

> 来自两件真实案件 24 条代理批注的共性缺陷。生成规则见 `disclosure_builder.md`「方案骨架先行」「公式随步走」「术语定义与数据血缘」「模糊限定词与观测粒度」四门禁；本节为成稿后复核，发现问题**先改方案骨架、再联动改各视图**，不得只改单处。

- [ ] **模块-步骤对应**：三、（三）每个模块能对应到流程中的步骤；流程每个步骤能找到执行它的模块；同一技术动作在各视图中名称与含义一致（无「提取系数」vs「计算系数」式漂移）。

- [ ] **保护支撑核对表（内部留档，逐条必答）**：对第五章**每条**技术关键点与从属保护点，列表回答「具体体现在方案中的哪部分」——支撑步骤（Sx）＋公式（式 (n)，计算类必填）＋实施例（如有）。任何一条答不出即为**保护点无正文支撑**，处置二选一：补全第三章实施方案，或降级/删除该保护点；**仅在「可替代实施方式」出现或全文只有一句话带过的特征，不得保留为保护点**。（代理批注原型：连续四条「具体体现在方案中的哪部分？」）

- [ ] **数据血缘抽查**：抽 2–3 个派生特征，正文能答出「由哪一步的哪些量按什么规则算出」；原始采集清单与派生特征清单未混写。
- [ ] **模糊限定词与粒度**：判定语境的模糊限定词已按三选一量化或注明示例阈值待标定（`delivery_gate.py` C11 WARN 列表逐处判定）；「定位/映射/识别」类主张的输出粒度未超出输入数据粒度支撑，超出处已降级为「候选＋置信度」措辞。

- [ ] **架构变化补充查新**：本轮迭代若发生数据来源/主要证据模态/定位方式/核心决策链/独权主线的实质变化（见 `observability_and_multimodal_evidence.md` §五），已执行针对性补充检索并回写 `risk_grade` 与 `evaluation_status`；未补检的不得沿用旧查新结论定稿。
- [ ] **实施参数未入独权区**：`delivery_gate.py` C15 WARN 列出的第五章独权区「数字+单位」已逐处判定——属实施参数的已上位化（「预设周期/预设阈值」）并把具体值移实施例/从属。

## 8.2 公式与参数一致性

**Step 8 必做（含公式时）**：除符号体例与跨节一致外，须**主动复核公式是否正确、公式逻辑是否与第三章叙述一致**（等同用户会提出的「检查公式和公式逻辑是否有误，有误请调整」）；发现问题**直接改稿**，勿仅提示用户自行修改。

### 符号与体例

- [ ] **符号表（3.4.1）**：全文含公式时是否已设 **3.4.1** 并 **先定义符号**（含义、下标、量纲）；式 (1) 及后文每个符号是否均已在表中定义？
- [ ] **formula manifest**：关键公式是否已进入 `formula_manifest`（字段含 id、number、title、latex、display、dimension_check、owner_step），正文公式是否与 manifest 的 `latex`/`number` 一致，未临场重拼？`owner_step` 是否全部非空且对应真实步骤（见 §8.1 公式-步骤绑定）？
- [ ] **量纲校核**：manifest 中每条关键公式是否含 `dimension_check`；是否避免把有单位的能量状态（如 \(B_{s,t}\)，kWh）误称为无量纲 SOC？
- [ ] **维度下标**：是否存在 `^{cpu}`、`^{mem}`、`^{io}` 等 **上标表示维度** 的写法？若有须改为 `b_{i,\mathrm{cpu}}`、`a_{j,\mathrm{mem}}` 等 **下标 + `\mathrm{}`** 形式（见 **`disclosure_builder.md` §7.7**）
- [ ] **字母多义**：同一字母是否兼指任务侧与节点侧等不同对象？若有须拆分符号（如任务用 \(b\)、节点用 \(g\)）
- [ ] **公式表述一致**：同一物理量在不同公式、段落中是否 **同形同义**（如权重公式、调整系数、匹配分 \(M_{ij}\) 等）
- [ ] **LaTeX 体例**：行内/块级分隔符是否全文统一（`\(...\)`/`\[...\]` 或 `$`/`$$` 二选一）；块级公式是否尽量单行；是否避免 `\text{且}` 等易渲染失败写法
- [ ] **3.5 与符号表**：3.5 参数表「符号」列是否与 3.4.1 **逐字同形**
- [ ] **阈值范围**：与正文一致（如 0.5–1.5、0.8–1.2 等）
- [ ] **参数命名**：全文统一，避免同义不同名混用
- [ ] **实施例数值**：与 3.5 关键技术参数对应，不冲突

- [ ] **式面正确性**：各式是否无明显笔误（运算符、括号配对、上下标错位、同一式内符号与符号表不符、缺项/多写项、指数或分母写错等）？
- [ ] **约束与不等式方向**：公式中的 `\leq`/`\geq`/正负号是否与文字含义一致（如「饱和度」「有余量」「限频间隔」等）；多条件「且/或」是否与 3.4 流程分支一致？
- [ ] **公式与流程互推**：3.4.1 主公式（含式 (1)）及衍生式，能否与 **3.4 流程说明**（各步骤 S1—Sn）、**3.3 模块职责** 逐步对应？叙述中的打分、重排、限频、窗口聚合等是否在公式中有体现，**无**「文字一套、公式另一套」？
- [ ] **边界与特殊情形**：空队列、单节点、分母为零、指标缺失、达到上下界等情形，公式或正文是否给出合理处理或说明（至少不与主公式矛盾）？
- [ ] **量纲与取值**：符号表声明的量纲/取值范围是否与公式用法一致（如权重为正、比例在 0—1、计数为非负整数等）？
- [ ] **定义顺序与循环依赖**：每个派生量能否按「先定义后使用」的顺序求值？若存在互依（如分层键 l(t) 按风速段划分、而风速估计又依赖 l(t)），是否已写明**初始化、更新规则与停机条件**（迭代次数或收敛判据）？
- [ ] **多组可调参数职责分界**：同一目标量涉及两组以上可调参数/两级拟合（如波动代理系数与标准差校准因子）时，各自职责是否写清（谁定绝对量级、谁定残差修正），避免「重复校准、技术边界不清」质疑？
- [ ] **周期量与圆周统计**：角度/相位/时刻等周期量的差值与统计是否采用**有符号圆周差**（归一区间明示，如 [−180°, 180°)）与圆周统计量，避免 0°/360° 环绕导致的偏差误判？
- [ ] **修订联动**：若修正公式或逻辑，是否已同步改 **3.4 文字**、**3.5 参数**、**第六章实施例** 及 **3.4.1 符号表**（见 §7.7 跨节一致）？

### 数值可复现（含关键量化效果时必做）

**问题特征（本节要防的）**：公式**写得对**、叙述**前后一致**，但写入正文的**具体数值或趋势断言算错了**（手填/转写自旧参数，或方向标反）。符号与逻辑核对抓不到这类错，须**真的把数算一遍**。适用于任何“优点/实施例/技术效果依赖具体数值或趋势”的交底书（如“相对相差约 X%”“临界值 Y”“某量随 Z 升高/降低”）；无关键量化效果的交底书本节为空操作。

**不变量：任何关键数值/趋势，未经第二次独立核对，不得交付。** 核对方式按数值**来源**分三层：

- **一层（能重算·优先）**：用户已有可执行模型/自带断言（如项目内 `*.py` 及其 `--test-only`）时**必须优先复用**；数值应在生成时即由计算产出，**不得手填或从旧稿转写**。
- **二层（有公式无代码）**：用交底书**自身公式**建最小 `numeric_check` spec 交 **`tools/qa_numeric_reproduce.py`** 重算——`value_checks`（稿值＝算值）、`monotonic_checks`（“随 X 升高/降低”方向）、`claim_checks`（正文所印值）。
- **三层（无可重算来源：实验/仿真/实测/外部数据）——设决策点，不默认展开**：当关键数值无法由公式或用户模型机器复现时，**不要闷头启动大核验、也不要反复空转或臆造数据**。而是：
  1. **停在决策点**，向用户说明：哪些数值属此类、为何不能机器复现；
  2. **主动列出**再核验所需的**背景信息/输入资料**（实验记录、仿真工程或输出文件、量测数据、参数来源等），请用户补充；
  3. 由**用户决定**：(a) 提供资料后展开人工二次核对（溯源 + 独立复核 + 一致性/量纲/量级/方向 sanity）；(b) 暂标“**待核（provenance-only·非机器复现）**”，记入证据包与交付记录、按 WARN 交付；(c) 略过。
  - **缺资料时默认取 (b)**，不无限追问、不进入无法收敛的核验循环。

- [ ] 上述层级已执行；发现稿值/方向不符**直接改稿**，并联动 3.5、实施例、优点及相关从属保护点；复算脚本/spec 或溯源记录作内部证据留档（不入正文）。

## 8.5 代理人审稿门禁与交付检查记录（必做）

本节用于判断本轮交付是否达到“可供代理人审稿”的基本质量，并把检查结果留在案件目录。**不得**把本节表格、PASS/WARN/FAIL 或自检清单写入交底书正文。

### PASS / WARN / FAIL 定义与用户可见映射

| 内部状态 | 用户可见文本 | 含义 | 是否可作为本轮交付 |
|---|---|---|---|
| PASS | **代理人审稿就绪** | 结构完整、区别特征和技术效果闭环、查新结论已写入、格式与图示基本可用 | 可交付给用户用于代理人审稿；不表示专利性通过、可授权或可直接提交专利局 |
| WARN | **阶段稿，存在待补项** | 可作为阶段稿，但仍有明确待补项，如实验数据、正式附图、联系人信息、代理人口径确认等 | 可交付，但回复中须列明待补项和风险，不得称为最终完成稿 |
| FAIL | **未达到交付条件** | 存在关键缺陷，如无查新结论、核心区别特征不清、技术效果无支撑、正文残留自检/内部流程、缺少交付文件 | 不得作为定稿交付；先修正关键缺陷 |

`PASS/WARN/FAIL` 可继续写入机器输出和内部检查记录；面向用户的正文与交付回复须使用上表中文状态，可在括号中附内部码，但不得单独展示 `PASS` 使其被误解为专利性或授权结论。

### 机器门禁（v3.8.0，先跑）

在下面的人工检查项之前，先运行统一交付门禁：

```text
python tools/delivery_gate.py --case-dir "{案件目录}" --md "{案件名_时间戳.md}" --docx "{案件名_时间戳.docx}" [--manifest <manifest.yaml>] [--numeric-spec <numeric_check.json>] [--preview-skipped]
```

以输出的 `DELIVERY_GATE_JSON` 最后一行为准：`FAIL` 先修正后再走下面的人工检查；`WARN` 把 `warns` 与 `user_fill` 逐条抄入本轮回复和交付检查记录的待补项；`PASS` 才继续。该工具默认已追加 `交底书交付检查记录.md`（除非传 `--no-record`），下面「留档要求」无需重复手工写入，只需核对内容一致。**机器门禁只覆盖占位符、表格合计、字段标签、公式段落残留、命名规范、确认点产物存在性、数值复现和版本自报——不覆盖下面的语义类检查（逻辑闭环、区别特征、技术效果支撑等），两者都要做。**

- **FAIL**：交底书 1.1 中把未核验、不可打开或仅为 CNIPA EPUB 提示路径的 URL 写成已核验公开源；或核心查新文献无来源状态；或没有执行查新却写出 A/B/C 式结论。

- **B 路线（结构有限辅助）**：最高 WARN，附注「本技能对结构类方案不做创造性评估，请代理人重点审查创造性支撑、附图完整性和物理机理依据」。

# 交底书生成前摘要预览（Step 6）

## 目的

在输出完整长文前降低返工：先展示结构化摘要，请用户 **确认 / 调整方向**。

若用户明确要求跳过预览，可直接进入 `disclosure_builder.md` 生成全文。

## 摘要应包含

- 选定专利点名称（工作标题）
- 解决的技术问题：对应现有技术缺点，1–3 条
- 核心创新模块或步骤（3–6 条）
- 与检索到的**最相近**现有技术的区别（1 段）

## 结构与保护策略确认清单（确认点 4，随摘要一并请用户确认）

预览时逐项询问（用户可**明确**跳过——跳过时在案件记录登记「确认点 4 跳过放行」，不得默认视为已确认；答复落档，供 Step 7 遵守）：

- **题名**：简洁题名是否 ≤25 字、用户是否接受（见 `patent_points_analyzer.md`「题名规则」）；
- **主线自然度**：独权主线是否存在"靠堆限定成案"的痕迹；若有，说明原因和保护范围影响；
- **保护组合偏向**：偏方法 / 系统 / 方法+系统 / 四客体；是否接受"较宽独权 + 从属收缩"的布局；
- **保密边界**：**是否有不希望公开的实施细节**（商业秘密）——不愿公开的内容不得写入说明书，须与充分公开要求权衡后由用户决定去留；
- **技术效果表述**：是否需要弱化定量效果（无数据支撑的百分比不写，定性效果标注证据等级）；
- **实施例降级**：哪些方案放实施例/从属特征而非核心保护点。

## 可选确认语

```
以上方向是否确认？确认后将按模版输出完整技术交底书，含 mermaid 系统框图与流程图（定稿时将转为 PNG 并同时交付 .md 与 .docx）。
```

## 禁止写入

摘要 Markdown **末尾不得**追加技能仓库名、`examples/` 路径、「教学示例」「虚构」「不构成法律承诺」等脚注（与 `disclosure_builder.md` 对定稿的要求一致）。

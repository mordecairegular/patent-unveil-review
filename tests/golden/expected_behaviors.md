# v3.11 Golden Cases：预期行为

本文件是 `cases.yaml` 的人工判分说明。Golden 只验证**路由、边界、状态、产物和门禁行为**，不以固定措辞逐字匹配，也不评价某项发明最终是否具备新颖性或创造性。

## 套件级不变量

1. 已有稿上的补充、纠错或批注处理必须进入 `revise`，不得无理由回到候选池或 Step 3 全文挖掘。
2. 新修订稿另存，不覆盖基线；需要 diff 时保留基线与修订根目录。
3. 代理意见原文逐字保留；“意见理解”另列，不能替代原文。
4. 内部判断只用“采纳/拒绝/存疑”；正式回复只用“已落实/部分落实/待补充材料后落实/暂未落实”。
5. 已落实或部分落实项须有可解析的 ASCII 机器锚点，多个锚点用半角分号分隔。
6. 新查新输出只使用 `risk_grade: A|B|C|null` + `evaluation_status`；证据不足、检索受阻、待核验不是风险等级。
7. 探针零命中只能表述为“探针范围内未检出”，不得外推为不存在现有技术。
8. 内部 PASS 对外显示“代理人审稿就绪”，不得解释为专利性通过、保证授权或可直接提交。

## 锚点与状态判分口径

- 合法命名空间：`STEP`、`DECISION`、`EQ`、`FIG`、`KP`、`SECTION`、`MVP`、`FILE`、`DELETE`。
- 多锚点示例：`STEP:S4; FIG:2; KP:3`。
- 删除示例：`DELETE:KP:3`；MVP 示例：`MVP:tools/qa_numeric_reproduce.py`。
- 最终状态：`CLOSED` 对应已落实，`PARTIAL` 对应部分落实，`OPEN` 对应待补材料或暂未落实。
- C17 无基线时只能 WARN/SKIP；基线存在且锚点区块规范化后完全相同才 FAIL；仅形式性变化且相似度不低于 0.98 为 WARN。

## 逐案例预期

### GC01｜带批注 DOCX 要求修改

**通过**：识别为 `revise.comment_closure`；完成批注提取、点批注作用范围判断、overlay、内部分诊、新版本、完整处置矩阵和需要时的正式回复。矩阵每行包含原文、意见理解、内外状态、人类位置、机器锚点、是否影响 MVP/计算、联动检查和最终状态。

**失败**：启动 T0/候选池；改写批注原文；缺少矩阵或新稿；只写“已修改”而无位置/锚点；正式回复直接使用“拒绝/存疑”作为处理结果。

### GC02｜已有稿补充实施例

**通过**：进入 `revise.merger`，读取基线和新增材料，仅改实施例及必要联动位置；生成新时间戳 `.md/.docx`，保留旧稿并更新修订日志、合并摘要。

**失败**：覆盖旧稿；重新做候选池或完整查新；大段改写与新增实施例无关的章节；没有落盘新版本。

### GC03｜用户指出公式可能错误

**通过**：进入 `revise.correction`；先核对 DOCX 渲染/OMML、原式、公式清单、量纲和流程逻辑，再决定是否修改。修改时联动符号表、正文步骤、参数表、实施例与保护点。

**失败**：把纯文本提取的公式空白当作真实缺陷；照单修改；只报告错误不改稿（除非缺少决定正确写法的必要事实，并明确暂停原因）。

### GC04｜明确主题只要求查新

**通过**：直接进入 `search`，不启动 T0；按证据模型建立案件级查新产物，并逐方向输出 `risk_grade` 与 `evaluation_status`。无法评级时对外写“暂不评级”及具体缺口。

**失败**：要求确认候选池边界；输出 D/partial-D；把渠道失败写成无结果；未核验来源被当成稳定证据。

### GC05｜询问业务可申请哪些方向

**通过**：进入 `mine`，先完成主题边界卡；冷启动痛点标为假设；执行探针、生成 3–5 张主题卡，并经确认点 2 后才进入案件级流程。

**失败**：直接承诺方向可授权；未检索就给 A/B/C；把一般行业事实仅凭用户回答写成已证实；用限定词堆叠制造主推方向。

### GC06｜探针检索零命中

**通过**：明确“探针范围内未检出”，解释词块/覆盖/伪问题三类可能；检查技术问题实在性。当前证据不足时返回 `risk_grade: null`、`evaluation_status: insufficient_evidence`。

**失败**：写“没有相关现有技术”“具备新颖性”；把未跑渠道写成未检出；因零命中自动给低风险等级。

### GC07｜三条意见、两条回复

**通过**：C14 返回 FAIL，明确顶层原批注为 3、正式逐条回复为 2，并指出缺失编号；不把回复线程算作新增代理意见。

**失败**：返回 PASS/WARN；只提醒“可能漏项”却不标 FAIL；用标题或摘要行数替代结构化编号计数。

### GC08｜声称修改 STEP:S4，但无实际变化

**通过**：C16 能解析 `STEP:S4`，C17 对基线/修订目标区块规范化比较后发现 100% 相同，返回 FAIL，并说明“检测不到声称的修改”。

**失败**：因整篇其它位置有变化而 PASS；仅相信回复散文；返回 WARN 代替明确的无 diff FAIL。

### GC09｜只改标点或空格

**通过**：C17 返回 WARN，说明目标区块只有极小或形式性变化，须人工判断是否真正解决意见；不将 WARN 表述为语义落实。

**失败**：返回 PASS；把可定位且存在微小 diff 的案例误判为 C16 FAIL；因无实质语义变化而误判 C17 无 diff FAIL（除非规范化后确为 100% 相同，此时应按 GC08）。

### GC10｜要求深度独立专业审阅

**通过**：明确独立法律/专利性审阅与授权保证不属于本 Skill 核心能力，建议专用审阅 Agent 或专利代理人；可说明本 Skill 能承担基础逻辑、MVP/计算复核和交付格式检查。

**失败**：冒充代理人；保证授权；把内部 PASS 解释为专利性通过；在未说明能力边界的情况下输出确定法律结论。

## 判分结果

每次运行按案例记录：

- `PASS`：全部 required 行为出现，且无 forbidden 行为；
- `WARN`：主路由正确，但存在不影响核心判定的措辞/产物说明遗漏，须写明人工判断；
- `FAIL`：路由、强制产物、状态枚举、计数/diff 门禁或职业边界任一核心条件不满足。

这里的 Golden `PASS/WARN/FAIL` 是**测试结果**，不是交底书交付状态，也不是专利性判断。
